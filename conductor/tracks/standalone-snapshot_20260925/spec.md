## Summary

Add a `standalone/` directory with one self-contained script per backend, each listing its own
requirements and running with one command, plus a document explaining the pipeline. The directory
is detached from the package so it can be uploaded on its own as a check of progress.

## Context

Audio Transcriber is a modular transcription pipeline: engines are plug-ins behind one backend
interface, and every backend emits the same transcript schema — a bare JSON array of segments with
`start_time`, `end_time`, `speaker`, `spoken_language`, `text`. The team's audio is English with
Spanish speakers who code-switch, so segments carry the language actually spoken and, with
diarization, who spoke. Two backends exist: `faster-whisper` (local, the default) and
`elevenlabs-scribe` (hosted, Scribe v2). Quality is measured against the Bangor Miami corpus and
the reports are committed.

The package itself spans ~3,800 lines across the pipeline, registry, manifest and backends. A
reviewer checking progress needs something smaller: a file they can read top to bottom and run.

## Motivation

Show that the work was done, and let someone test it quickly without installing the package or
reading its internals.

## Risk Assessment

| Risk | Mitigation |
| ---- | ---------- |
| The copies drift from `src/` as the package changes | README marks the directory as a dated snapshot of a named commit. pytest never collects it; Ruff still lints it, since the scripts import nothing from `src/` and drift cannot break their lint |
| Secrets end up in the upload | Keys are read from the environment only, never hard-coded; `standalone/.gitignore` ignores `.env` |
| The live ElevenLabs run spends free-tier credits | One clip of 30–60 s; confirm with the user before the call |
| Corpus text leaks into the document | Only the committed aggregate scores are quoted, with the corpus citation; no TalkBank or Bangor transcript text |

## Out of Scope

- Changing the package, its backends, the CLI, or the transcript schema
- Tests for the standalone scripts — they are verified by a real run, not by the suite
- The run manifest, per-run output directory, batch input and error reports: the scripts take one
  file and print one transcript
- Packaging the directory (no `pyproject.toml`, no Docker image)

## Technical Notes

- **faster-whisper script:** decode with ffmpeg to 16 kHz mono, transcribe with `large-v3`
  (falling back to CPU / `int8` when there is no GPU), with chunked language detection limited to
  English and Spanish, as the backend doc recommends for this audio. Diarization with pyannote
  `speaker-diarization-community-1` (needs `HF_TOKEN` and the accepted Hugging Face gate), speakers
  assigned per word. A `--no-diarization` flag skips pyannote and sets `speaker` to `null`.
- **elevenlabs-scribe script:** Scribe v2 through the official SDK with `diarize=True`; Scribe
  diarizes itself, at no extra cost. One `spoken_language` per file, as in the backend.
- The scripts simplify the backend code, but keep its behaviour on the points the README
  describes. Where they simplify, a comment says what the full backend does differently.
- Output goes to stdout; logs go to stderr, so `python script.py a.wav > a.json` works.

# Specification: Default Whisper Model to large-v3

**Track ID:** default-large-v3_20260923
**Type:** Chore
**Created:** 2026-09-23
**Status:** Draft

## Summary

Change the faster-whisper backend's default `model` option from `base` to `large-v3`, so a run
that passes no `--option model=...` transcribes with `large-v3`.

## Context

The faster-whisper backend sets its defaults in `_DEFAULTS`
(`src/audio_transcriber/backends/faster_whisper.py`). The README, `docs/evaluation.md` and
`docs/backends/faster-whisper.md` already pass `--option model=large-v3` in their examples; only
the implicit default is `base`.

## Motivation

A change of perspective on what the default should be. There is no triggering defect or measured
shortfall behind it.

## Success Criteria

- [ ] A run with no `model` option uses `large-v3`, and the run manifest records `large-v3`
- [ ] A test pins the default (the existing assertion in `tests/test_faster_whisper.py` that
      expects `base` is updated to `large-v3`)
- [ ] `docs/backends/faster-whisper.md` states the new default and its cost: 3.1 GB download,
      about 3.8 GB VRAM at `float16`, about 70 s first load
- [ ] The docs carry a note on the risks below: slow on CPU-only hosts, and may not fit smaller GPUs,
      with the `model=` override (e.g. `tiny`, `base`) as the way out
- [ ] `pytest`, `ruff check .` and `ruff format --check .` pass

## Risk Assessment

- **CPU-only hosts get a much slower default**, and a first run downloads 3.1 GB unannounced.
  Mitigated by a docs note.
- **Smaller GPUs may run out of memory**: about 3.8 GB VRAM at `float16`, more with diarization on
  the same device. Mitigated by a docs note.
- **Cross-run comparison**: "the default" now means a different model before and after this change.
  The manifest records the model, so runs remain traceable.
- **No contract change**: the backend interface, transcript schema and manifest format are
  untouched, so the workflow's pause-for-approval rule does not apply.

## Out of Scope

- Tests that pass `model="tiny"` explicitly stay as they are; `tiny` is deliberate, to keep tests fast
- Any other default (`device`, `compute_type`, `beam_size`, diarization model)
- Runtime warnings or logging about the model choice

## Technical Notes

One-line change to `_DEFAULTS["model"]`, one test assertion, and docs.
